---
name: deps_uv
description: update Python dependencies (uv) to latest stable
---

Update a Python project's dependencies under uv (`pyproject.toml` + `uv.lock`).

- **Detect**: `pyproject.toml` + `uv.lock`. If there's a `poetry.lock` instead,
  use `:deps_poetry`. If there's no lockfile at all (a bare `requirements.txt`
  project), see `:deps_pip`.

- **Current lockfile**: uv deliberately does NOT roll forward on new releases
  — the lockfile only changes when you ask. `uv lock --check` verifies it
  matches the manifest; `uv lock` re-resolves against the current constraints.

- **Latest stable**: `uv lock --upgrade` re-resolves EVERYTHING to the latest
  stable (crossing ranges); `uv lock --upgrade-package <pkg>` one package
  (repeatable). `uv add --upgrade <pkg>` upgrades a single dependency in the
  manifest and lock together. `uv tree --outdated` lists what's behind.

- **Lockfile**: `uv.lock` is regenerated by any of the above; commit it with
  the manifest. CI gates run `uv sync --locked` (verify) or `--frozen` (use as
  is); a `--locked` failure means the lockfile didn't get regenerated.

- **Verify**: `uv sync` (or `uv run`), then the project's test/lint/build
  commands. Check the installed copy (`uv run python -c "import <pkg>;
  print(<pkg>.__file__)"`, then read that path) for changed APIs.

- **Gotchas**: uv's resolution is universal (all platforms/extras in one
  lockfile) — a bump can change the lock for targets you don't run locally;
  trust `uv.lock` as generated. Python version constraints (`requires-python`)
  cap what resolves — a `requires-python` bump may be needed before the newest
  packages are selectable. `uv` treats prereleases as excluded unless opted in.
