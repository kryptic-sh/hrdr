---
name: deps_pip
description: update Python dependencies (pip / requirements files) to latest stable
---

Update a Python project that manages dependencies with plain pip and
`requirements*.txt` files (no `pyproject.toml` lockfile, no uv, no poetry).

- **Detect**: `requirements.txt`, `requirements-dev.txt` etc. and no
  `uv.lock`/`poetry.lock`. If the project keeps its pins in a lockfile-style
  requirements file generated by pip-tools, use the pip-tools flow below; a
  bare `requirements.txt` of direct pins is the plain-pip flow.

- **Plain pip (direct pins)**:
  - `pip list --outdated` — what's behind.
  - `pip install --upgrade <pkg>` — upgrade one; edit the requirements file to
    match the new pin. For "everything": bump each pin in the file and run
    `pip install -r requirements.txt`.
  - Verification is `pip install -r requirements.txt` in a clean environment
    (or a venv) — pip has no frozen-lockfile CI gate because there's no
    lockfile; the requirements file IS the source of truth.

- **pip-tools (compiled requirements)**:
  - `pip-compile --upgrade` — re-resolve `requirements.in` → `requirements.txt`
    to the latest stable; `pip-compile --upgrade-package <pkg>` one package.
  - `pip-compile --output-file requirements-dev.txt requirements-dev.in` for
    each compiled file. Never hand-edit the compiled output — regenerate it.
  - `pip-sync` installs exactly the compiled set (the frozen install).

- **Verify**: install, then the project's test/lint commands. Check the
  installed copy (`pip show <pkg>` → Location, or `python -c "import <pkg>;
  print(<pkg>.__file__)"`) for changed APIs.

- **Gotchas**: no resolver lockfile means no reproducibility gate — pin exact
  versions in requirements files, and never leave a bare unpinned name unless
  the project's own workflow does. Watch `requires-python` compat: pip resolves
  against the interpreter you run it with. `pip index versions <pkg>` lists
  published versions (stable = non-prerelease).
